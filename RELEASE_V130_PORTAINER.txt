VK TAXI V130 — безопасное обновление GitHub / Portainer
======================================================

Что изменено
------------
1. Все новые заявки диспетчера сразу публикуются в водительском чате.
2. Новые заявки пассажиров с указанной ценой сразу публикуются в водительском чате.
3. Свободные водители для этих заявок автоматически в боте не перебираются.
4. Кнопка «Поехать» на заявке с ценой сразу принимает цену клиента.
5. Если водитель свободен, заявка становится основной и бот просит указать время прибытия.
6. Если водитель уже выполняет заявку, новая становится параллельной.
7. Одновременно у водителя может быть только одна параллельная заявка.
8. После завершения основной и перехода к параллельной водитель снова может взять из чата ещё одну параллельную заявку.
9. В водительском чате карточка заменяется сообщением вида:
   «Заявку #423 взял водитель Иван Иванов», где имя — ссылка на профиль VK.
10. Цена клиента сохраняется как согласованная цена заявки.

База данных
-----------
Новая миграция не требуется: структура таблиц не менялась.
Существующие заявки и данные не удаляются.

Обязательная настройка
----------------------
В переменных Stack должна быть настроена переменная:
DRIVER_FALLBACK_CHAT_PEER_ID

Можно указать номер беседы или полный peer_id. Бот должен иметь доступ к беседе.
Также администратор может назначить беседу командой внутри нужного чата:
!назначить чат заявок

Рекомендуемое обновление
------------------------
1. Сделайте резервную копию PostgreSQL штатным scripts/backup.sh.
2. Сохраните текущий commit/tag GitHub, чтобы быстро откатиться.
3. Загрузите содержимое папки vk-taxi-v130 в ветку обновления.
4. Дождитесь успешного GitHub Actions Validate Docker release.
5. В Portainer откройте Stack бота и выполните Update the stack / Pull and redeploy.
6. Не удаляйте volume postgres_data.
7. После запуска проверьте логи migrate, bot и admin.

Проверка после развёртывания
----------------------------
1. Создайте тестовую заявку диспетчером — карточка должна сразу появиться в водительском чате.
2. Создайте пассажирскую заявку с ценой — карточка должна сразу появиться там же.
3. Свободным водителем нажмите «Поехать» — бот должен запросить ETA.
4. Занятым водителем нажмите «Поехать» — заявка должна стать параллельной.
5. Попробуйте взять ещё одну параллельную — бот должен отказать.
6. Завершите основную заявку — параллельная должна стать основной.
7. Возьмите ещё одну заявку из чата — она должна стать новой параллельной.
8. Проверьте сообщение в беседе с номером заявки и кликабельным именем водителя.

Откат
-----
1. Верните предыдущий commit/tag (V129).
2. Выполните Update the stack / Pull and redeploy в Portainer.
3. Базу данных откатывать не нужно, так как V130 не добавляет миграций.

Проверки перед выпуском
-----------------------
- Python compileall: успешно.
- 559 автоматических регрессионных тестов: успешно.
- Docker Compose YAML и порядок зависимостей сервисов: проверены.
- В этой песочнице не было команды docker, поэтому фактическая сборка Docker-образа здесь не запускалась. Её должен выполнить GitHub Actions/Portainer.
