# V122 — сброс счётчиков при уже пустой истории

- Исправлен ранний выход в административном сбросе.
- Раньше при отсутствии завершённых/отменённых записей обработчик возвращался до PostgreSQL `setval`, поэтому пустая таблица продолжала выдавать старый следующий ID.
- Теперь счётчики `orders` и `bookings` синхронизируются даже тогда, когда история уже пуста.
- Для пустой таблицы следующая запись получает `#1`.
- Если в таблице всё же есть сохранённая запись, используется `max(id) + 1`, чтобы не допустить дублирования.
- Сохранены отмена броней из V121 и исправление миграции V120.
