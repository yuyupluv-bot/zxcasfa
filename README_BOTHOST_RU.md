# Бот + админка + Firebase на BotHost

## Что изменено

- `bothost_main.py` запускает бота и веб-админку в одном контейнере, но в разных процессах.
- Если один процесс завершается, перезапускается только он, с задержкой до 60 секунд. Второй продолжает работать. При остановке контейнера отправляется SIGTERM.
- Перед запуском обоих процессов один раз выполняются миграции. При ошибке миграции запуск останавливается: работать с неполной схемой нельзя.
- Исправлена миграция `0049_driver_device_secret`: новая база уже могла содержать колонку из начального `Base.metadata.create_all`, из-за чего возникала ошибка DuplicateColumn.
- Админка работает через Gunicorn на `0.0.0.0:$PORT`. Сохранён её watchdog; сохранён watchdog бота.
- Поддержка Firebase, регистрация телефонов, обновление FCM-токенов и настройки звуков сохранены.
- Готовый APK из исходного архива лежит в `downloads/BEZTAKSY.apk`. Он НЕ пересобирался. В нём обнаружен адрес `https://panel.bezrateadminps.ru`.
- Приватный ключ Firebase и Android-конфигурация `google-services.json` не включены в выдаваемый архив. Они остаются в вашем исходном архиве. Удаление копии ключа из кода НЕ отключает Firebase: передайте ключ через переменную окружения.

Это подготовленная сборка, а не уже выполненный деплой в вашем аккаунте.

## 1. До запуска: база и резервная копия

Нужна доступная **PostgreSQL**, общая для бота и админки. SQLite этот проект не поддерживает.

BotHost запускает контейнер приложения. PostgreSQL не появится сама из `docker-compose.yml`: Compose в этом варианте не запускается. Используйте существующую доступную PostgreSQL или отдельный сервер/сервис PostgreSQL.

Обязательная переменная:

```dotenv
DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/DBNAME?sslmode=require
```

- Возьмите реальный URL у своего провайдера PostgreSQL; не копируйте USER/PASSWORD/HOST буквально.
- `localhost`, `127.0.0.1` и Compose-хост `db` обычно НЕ указывают на вашу внешнюю БД из контейнера BotHost.
- Если PostgreSQL осталась на недоступном сервере Beget, одного переноса Python-кода недостаточно. Нужны доступ к БД или её резервная копия и восстановление на доступном PostgreSQL.
- URL должен быть доступен с BotHost; проверьте firewall/список разрешённых адресов.
- Если провайдер требует SSL, используйте выданные им параметры, например `sslmode=require`. Не отключайте SSL ради обхода ошибки.
- Спецсимволы в логине/пароле URL-кодируются. Лучше копировать готовую строку подключения из панели БД.
- Перед обновлением существующей базы сделайте `pg_dump` средствами своего провайдера. Не подключайте тестовые скрипты к рабочей БД.
- Остановите старого бота перед запуском нового: нельзя держать два экземпляра Long Poll для одного сообщества. При использовании новой БД сначала перенесите данные; пустая БД не содержит старых водителей и привязанных устройств.

## 2. Загрузка кода

### Из ZIP

В профиле BotHost включите «Загрузка бота из архива», затем на дашборде нажмите «Загрузить из архива». По документации BotHost эта функция доступна на Базовом/Pro и пока ограничена тестовой нодой; если недоступна, используйте Git.

Загрузите `vk-taxi-bothost-ready.zip`.

### Из Git

Распакуйте готовый архив и загрузите содержимое в свой приватный репозиторий. `Dockerfile`, `requirements.txt`, `bothost_main.py` должны находиться в корне проекта.

Не загружайте заполненные `.env`, Firebase JSON, `.b64`, дампы БД и ключи подписи Android в Git.

## 3. Настройки BotHost

В создании/настройках приложения:

| Поле | Значение |
|---|---|
| Язык | Python 3.11 |
| Главный файл | `bothost_main.py` |
| Собственный Dockerfile | Включить |
| Использовать домен / веб-интерфейс | Включить |
| Внутренний порт | `3000` |
| Команда запуска, если требуется отдельным полем | `python bothost_main.py` |

`bothost.json` уже указывает точку входа. Если поле «Главный файл» заполнено вручную, оно должно указывать туда же.

Не выбирайте `main.py`: он оставлен для запуска только бота и совместимости со старым Docker Compose. Не запускайте отдельно `web/app.py` с отладочным сервером.

В переменных окружения BotHost задайте значения из `.env.bothost.example`. **Минимум:**

```dotenv
DATABASE_URL=ваша_строка_PostgreSQL
VK_TOKEN=токен_сообщества_VK
VK_GROUP_ID=числовой_ID_сообщества_без_минуса
ADMIN_VK_IDS=ваш_числовой_ID_VK
SECRET_KEY=случайный_секрет_минимум_32_символа
ADMIN_LOGIN=ваш_логин
ADMIN_PASSWORD=ваш_сложный_пароль
PORT=3000
FLASK_COOKIE_SECURE=1
```

`ADMIN_VK_IDS` — администраторы бота, не логин веб-панели. Несколько ID разделяйте запятыми.

Для `SECRET_KEY` сгенерируйте значение локально:

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

Не меняйте SECRET_KEY при каждом рестарте: это сбрасывает сессии админки. Для водительского чата дополнительно задайте `VK_CHAT_USER_TOKEN`, `DRIVER_CHAT_PEER_ID`, `DRIVER_FALLBACK_CHAT_PEER_ID`, если используете эти возможности.

В сообществе VK включите сообщения, Long Poll API и события `message_new` и `message_reply`. Токен должен принадлежать этому сообществу и иметь необходимые права.

## 4. Домен: старый или новый

### Предпочтительно оставить panel.bezrateadminps.ru

Если упал только сервер Beget, домен необязательно менять. Важно, где обслуживаются DNS и есть ли к ним доступ.

1. Подключите свой домен `panel.bezrateadminps.ru` в настройках домена приложения BotHost.
2. Возьмите у BotHost точное DNS-назначение для вашего приложения.
3. В DNS-зоне `bezrateadminps.ru` замените запись поддомена `panel` согласно инструкции BotHost: A или CNAME — только тот тип и адрес, которые выдаст площадка. Не используйте случайный IP и не вводите `https://` в значение DNS-записи.
4. Если остаётся старая AAAA-запись на сервер Beget, согласуйте её с новой настройкой или удалите именно устаревшую запись. Иначе часть клиентов может идти на старый сервер по IPv6.
5. Дождитесь обновления DNS и выдачи HTTPS-сертификата на BotHost.
6. Проверьте `https://panel.bezrateadminps.ru/health` и вход в админку.

Хостинг сайта и управление доменом — разные вещи. Если панель DNS на Beget недоступна, менять записи нужно через доступного DNS-провайдера/регистратора или после восстановления доступа. Перенос NS требует переноса всех необходимых DNS-записей, включая почту; не делайте его вслепую.

Старый адрес в приложении продолжит вести на новый сервер только после корректного переключения DNS и HTTPS. При смене БД перенесите таблицы устройств/кодов и остальные данные либо привяжите телефоны заново.

### Новый автоматический адрес BotHost

Включите «Использовать домен» и используйте **фактически выданный** адрес BotHost. Новый домен можно использовать без Beget; выдумывать его заранее не нужно.

Админка работает на новом адресе без пересборки Python. Но существующий APK обращается к `https://panel.bezrateadminps.ru`, поэтому сам на новый адрес НЕ переключится. Firebase не изменяет URL сервера внутри APK.

Для нового адреса пересоберите приложение из `android-driver-app/`, вернув свой `app/google-services.json` из исходного архива:

```bash
cd android-driver-app
gradle :app:assembleRelease \
  -PDRIVER_APP_SERVER_URL=https://ВАШ_ВЫДАННЫЙ_ДОМЕН \
  -PPRIVACY_POLICY_URL=https://ВАШ_ВЫДАННЫЙ_ДОМЕН/privacy
```

Нужны Android SDK/JDK 17/Gradle и ваш прежний release keystore для обновления поверх установленного приложения. Их нет в серверной сборке. Для публикации обновления увеличьте versionCode. Сменой подписи нельзя незаметно заменить существующее приложение.

После сборки замените `downloads/BEZTAKSY.apk` новым APK и обновите код на BotHost. Сервер не компилирует Android-приложение при старте.

## 5. Firebase: обязательно для приложения уведомлений

### Передать ключ безопасно

Нужен service-account JSON **того же Firebase-проекта**, что и `google-services.json`, с которым собран APK. В исходном архиве идентификаторы проектов этих двух файлов совпадают. Это не означает, что ключ ещё действующий — проверяется отдельно.

Ключ в вашем исходном архиве:

```text
android-driver-app/app/secrets/firebase-service-account.json
```

`google-services.json` — другой файл: это клиентская конфигурация Android, не серверный приватный ключ.

На своём компьютере, рядом с распакованным проектом, выполните:

```bash
python -m scripts.firebase_prepare ПУТЬ_К_SERVICE_ACCOUNT.json --output firebase-secret.b64
```

Скрипт создаст файл с секретным содержимым, не выведет ключ в консоль и не перезапишет существующий файл. Скопируйте содержимое **в одну переменную BotHost**:

```dotenv
FIREBASE_SERVICE_ACCOUNT_B64=содержимое_файла_без_кавычек_и_переносов
VK_BOT_URL=https://vk.me/clubВАШ_ID
PUSH_SOUND_DIR=/app/data/push_sounds
```

Удалите временный `.b64` после настройки. Base64 — не шифрование. Не отправляйте это значение в чат и не коммитьте. Если сервисный ключ уже распространялся с исходниками, рекомендуется выпустить новый ключ в том же Firebase-проекте и отозвать старый после переключения.

Оба процесса получают переменную автоматически. Не нужно оставлять JSON внутри публичного репозитория. Альтернатива — приватный файл хостинга и `FIREBASE_SERVICE_ACCOUNT_FILE`, но путь должен реально существовать и читаться контейнером.

Firebase Cloud Messaging API должен быть включён в нужном проекте, а сервисный аккаунт — иметь право отправлять FCM. Не выдавайте лишние права для обхода ошибок.

### Проверка конфигурации

В терминале BotHost:

```bash
python -m scripts.check_firebase
```

Это проверка локальной загрузки учётных данных, а не доставки на телефон.

Для **осознанной отправки настоящего тестового уведомления** своему тестовому водителю:

```bash
python -m scripts.check_firebase --driver-id ВНУТРЕННИЙ_ID_ВОДИТЕЛЯ_ИЗ_БД
```

Это не VK ID. Команда отправляет событие `new_order` по настройкам сценария. Проверяйте только на своём тестовом телефоне. Успех FCM означает приём сообщения Firebase, но звук/уведомление нужно подтвердить на телефоне.

### Привязка телефона

1. Откройте `/driver-app` в админке: проверьте сценарии, включение, звук, длительность и вибрацию.
2. Установите APK с правильным адресом сервера. Скачать: `/driver-app/download.apk`.
3. Получите код привязки в меню водителя VK-бота и введите его в приложении.
4. Разрешите уведомления; отключите мешающие ограничения батареи/автозапуска по настройкам телефона. Проверьте, что уведомления и нужный сценарий включены в приложении.
5. Проверьте регистрацию устройства, тестовую заявку, сигнал и отмену.

Сценарии: `new_order`, `customer_price`, `dispatcher_order`, `parallel_order`, `cancelled`.

Звуки сохраняются в `/app/data/push_sounds`: это должно быть постоянное хранилище BotHost с правом записи для пользователя контейнера. Делайте отдельные резервные копии файлов и PostgreSQL. Токены телефонов и настройки лежат в PostgreSQL, не в папке звуков.

## 6. Признаки успешного запуска

В логах последовательно:

```text
STARTUP DATABASE OK: schema is ready
STARTUP BOTHOST DATABASE OK; starting bot and admin on PORT=3000
STARTUP VK OK: ...
STARTUP BOT OK: listening for VK events
```

Проверьте:

- `/live` → 200: отвечает HTTP-процесс, без проверки БД;
- `/health` или `/healthz` → 200: админка подключается к PostgreSQL;
- `/login` → форма входа; вход работает;
- `/driver-app` → настройки приложения после входа;
- `/driver-app/download.apk` → скачивается APK;
- обычное сообщение боту, создание/принятие/отмена тестовой заявки;
- привязку телефона и реальный push.

`/health` НЕ подтверждает подключение VK и доставку Firebase. Это проверяется отдельно логами и тестовыми действиями.

## 7. Если не работает

| Симптом | Что проверить |
|---|---|
| Ошибка отсутствующей переменной | Заполнить указанное имя в настройках BotHost; значения секретов не присылайте |
| 502/504 | Собственный Dockerfile, главный файл, домен, PORT=3000 и порт 3000 в панели; логи Gunicorn |
| Connection refused к localhost/db | DATABASE_URL должна указывать на доступную PostgreSQL, а не старый Compose-хост |
| Не работает БД на Beget | Нужен её доступный адрес или восстановление бэкапа; код сам не восстановит недоступные данные |
| Migration failed | Смотреть первую ошибку PostgreSQL/Alembic; не удалять рабочую БД и не пропускать миграции |
| Бот перезапускается, админка работает | Проверить VK_TOKEN, VK_GROUP_ID, Long Poll и события; второй экземпляр бота остановить |
| Возврат на логин | HTTPS, правильный домен, неизменный SECRET_KEY; для HTTPS FLASK_COOKIE_SECURE=1 |
| Firebase credentials missing | Проверить наличие FIREBASE_SERVICE_ACCOUNT_B64 и корректное base64-кодирование service-account JSON |
| Firebase initialized, но push нет | Локальная инициализация не подтверждает права FCM/активность ключа; проверить FCM API, проект, права и ошибки отправки |
| No active device | Привязать приложение к нужному водителю; при пустой новой БД старые привязки не переносятся автоматически |
| Disabled unregistered Firebase device | FCM-токен устарел: перепривязать приложение/проверить обновление токена |
| Приложение не регистрируется | APK может смотреть на старый домен; проверить DNS/HTTPS или пересобрать с новым адресом |
| Звук не загружается | Запись в /app/data/push_sounds, постоянное хранилище, HTTPS-доступ к /driver-app/sounds/... |
| Killed / код 137 | Не хватает памяти; увеличить лимит или уменьшить количество рабочих потоков/пулы |
