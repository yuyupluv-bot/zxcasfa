# V156 — первый этап стабилизации

Изменения не добавляют кнопки, разделы или новые пользовательские тексты.

## Исправлено

- Ручное назначение водителя из админки проходит через отдельный атомарный
  сервис: блокируются строки заказа, водителя и очереди; занятый, заблокированный
  или находящийся не на линии водитель не может получить второй заказ.
- В списке назначения отображаются только свободные водители из активной
  очереди.
- При назначении согласованно обновляются заказ, очередь, таймеры, состояние
  водителя и существующие уведомления.
- Android-приложение применяет настройки повтора и вибрации, асинхронно
  подготавливает сетевой звук и возвращается к системному сигналу при ошибке.
- Повторный push во время активного сигнала больше не затирает исходный уровень
  громкости уже максимальным значением.
- Firebase-токен устройства обновляется без повторного ввода pairing-кода.
  Сервер хранит только SHA-256 от отдельного секрета установки.
- Добавлены серверные границы для числовых настроек админки.
- Загрузка файлов в админку ограничена 10 МБ.
- Добавлены базовые HTTP security headers.
- Вход ограничивается как по IP, так и по логину; сравнение пароля из окружения
  выполняется constant-time.
- Админка больше не запускается с временным `SECRET_KEY` или после неуспешной
  миграции базы.
- `ADMIN_BIND_IP` теперь реально применяется в Docker Compose.

## База данных

Добавлена линейная миграция `0049_driver_device_secret`.

Перед обновлением необходимо сделать резервную копию PostgreSQL. Контейнер
`migrate` применит миграцию до запуска бота и админки.
