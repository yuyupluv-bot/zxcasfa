# V191 — запуск из Git на BotHost

## Исправление

- Docker теперь собирает и запускает проект из `/opt/vk-taxi`: исходники в образе не перекрываются возможным монтированием `/app`. Пути постоянных данных, звуков, журналов и секретов `/app/data`, `/app/logs`, `/app/secrets` не менялись.
- Миграция и дочерние процессы получают путь именно к проекту; при запуске миграции он явно добавляется в начало `sys.path`. Это защищает от совпадения имени с другим пакетом `common` и некоторых настроек Python.
- На этапе сборки проверяются наличие и фактический путь `common.db_migrate`: ожидается `BUILD MIGRATION MODULE OK`. При старте печатается `STARTUP SOURCE OK: project root=/opt/vk-taxi`. Настоящие ошибки БД по-прежнему блокируют запуск — миграции не отключены.
- Поиск APK сохраняет старые пути `/app/...`, затем дополнительно проверяет папку `downloads` в коде образа. Загрузка конфигурации из `/app/.env` сохранена как запасной вариант; переменные окружения приоритетнее.
- Сохранено исправление V190 параллельной заявки; схема базы и её содержимое не менялись.

## Проверки

Python 3.13 локально (производственный Docker использует Python 3.11). Сеть и база не использовались.

- 8 новых проверок запуска: реальный отдельный Python-процесс с конфликтующим `common`, `PYTHONSAFEPATH`, тестовая миграция, запуск/остановка обеих служб-заглушек, проверка наличия модуля при сборке, синтаксис Docker CMD и поиск APK — успешно.
- 13/13 тестов V190 параллельной заявки; 23/23 тестов V189; 2/2 прежних проверок APK; компиляция Python — успешно.
- Общий набор: 976 тестов, 31 failure и 26 errors; имена сбоев совпадают с предыдущим прогоном V190, новых имен сбоев нет. В этом полном прогоне было 7 из 8 новых тестов; восьмой добавлен и отдельно прошёл после начала общего прогона. Набор не является полностью зелёным.
- Docker/Podman в тестовой среде отсутствуют. Настоящие сборка образа, монтирование на BotHost, PostgreSQL, VK и Android не проверены. Тест запуска использует заглушку миграции, не настоящую БД. Точная причина ошибки в работающем контейнере не подтверждена; исправление защищает от перекрытия каталога и конфликта путей.

## Обновление через Git

Распакуйте архив и перенесите файлы проекта в корень нужной ветки репозитория с сохранением своих секретов и локальных данных. Если предыдущая версия V190 уже установлена без других изменений, для этого исправления изменены `Dockerfile`, `bothost_main.py`, `web/push_app.py`; тест и этот отчёт добавлены отдельно. После коммита нажмите «Обновить из Git» и дождитесь новой сборки. Базу, переменные окружения и том `/app/data` не удаляйте.

В логе новой сборки ожидается `BUILD MIGRATION MODULE OK`; в логе запуска — `STARTUP SOURCE OK` и после успешной миграции `STARTUP BOTHOST DATABASE OK`. Если после исправления появится другая ошибка, нужна её полная трассировка без секретов.
