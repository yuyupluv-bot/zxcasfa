# VK Taxi V167 — GitHub + Portainer без команд

Эта версия предназначена для развёртывания из приватного GitHub-репозитория через интерфейс Portainer. Файл `.env` на сервере не требуется: секреты вводятся в Portainer в разделе **Environment variables**.

## Что запускается

- PostgreSQL 16;
- сервис миграции базы;
- VK-бот;
- веб-админ-панель на порту `3000`.

PostgreSQL хранится в постоянном Docker Volume и не открывается в интернет. Обновление кода не удаляет базу.

## Что потребуется

- приватный репозиторий GitHub;
- GitHub Personal Access Token с правом чтения Contents этого репозитория;
- токен сообщества VK;
- пользовательский VK-токен, если используется водительский чат;
- ID сообщества и VK ID администраторов;
- логин и пароль веб-админки;
- при переносе данных — резервная копия старой PostgreSQL.

Не загружайте токены, пароли и `.env` в GitHub.

## 1. Создание приватного репозитория

1. Откройте GitHub → **New repository**.
2. Название, например: `vk-taxi-production`.
3. Выберите **Private**.
4. Не добавляйте README или `.gitignore`, потому что они уже есть в комплекте.
5. Создайте репозиторий.
6. Распакуйте архив V167 на своём компьютере.
7. В репозитории нажмите **Add file → Upload files**.
8. Перетащите содержимое распакованной папки, а не сам ZIP.
9. Проверьте, что `docker-compose.yml` лежит в корне.
10. Нажмите **Commit changes**.

Файл `.env` загружать нельзя. В архиве его нет.

## 2. GitHub-токен для Portainer

Создайте fine-grained Personal Access Token:

1. GitHub → Settings → Developer settings.
2. Personal access tokens → Fine-grained tokens.
3. Дайте доступ только к созданному приватному репозиторию.
4. Repository permissions → Contents → Read-only.
5. Сохраните токен в менеджере паролей.

## 3. Создание Stack в Portainer

1. Portainer → **Stacks**.
2. Нажмите **Add stack**.
3. Name: `vk-taxi`.
4. Build method: **Repository**.
5. Включите Authentication.
6. Username: логин GitHub.
7. Personal Access Token: созданный токен.
8. Repository URL: HTTPS-адрес приватного репозитория.
9. Repository reference: `refs/heads/main`.
10. Compose path: `docker-compose.yml`.

## 4. Переменные окружения в Portainer

Внизу страницы Stack откройте **Environment variables** и добавьте обязательные значения:

```text
POSTGRES_DB=taxi
POSTGRES_USER=taxi
POSTGRES_PASSWORD=<случайный hex-пароль>

VK_TOKEN=<токен сообщества>
VK_CHAT_USER_TOKEN=<пользовательский токен или пусто>
VK_GROUP_ID=<ID сообщества>
ADMIN_VK_IDS=<VK ID администраторов через запятую>

SECRET_KEY=<случайная строка 64 hex-символа>
ADMIN_LOGIN=admin
ADMIN_PASSWORD=<сложный пароль>

ADMIN_PORT=3000
FLASK_COOKIE_SECURE=0
TZ=Asia/Yekaterinburg
```

Полный список находится в `PORTAINER_ENV_VARIABLES.txt`.

Для `POSTGRES_PASSWORD` используйте только латинские буквы и цифры. Значения можно сгенерировать локально любым генератором паролей; терминал на сервере не требуется.

`FLASK_COOKIE_SECURE=0` нужен для первого открытия по `http://IP:3000`. После подключения HTTPS измените на `1`.

## 5. Первый запуск

Нажмите **Deploy the stack**.

Portainer:

1. скачает репозиторий;
2. соберёт образ;
3. запустит PostgreSQL;
4. дождётся healthcheck;
5. применит миграции;
6. запустит бота;
7. запустит админ-панель.

Откройте **Containers**. Ожидаемое состояние:

- `vk-taxi-db-1` — running/healthy;
- `vk-taxi-migrate-1` — exited с кодом `0`;
- `vk-taxi-bot-1` — running;
- `vk-taxi-admin-1` — running/healthy.

`migrate` не должен работать постоянно: успешное завершение с кодом `0` является нормой.

Админ-панель:

```text
http://IP_СЕРВЕРА:3000
```

## 6. Проверка логов без команд

Portainer → Containers → нужный контейнер → **Logs**.

В логах `bot` должна появиться строка:

```text
STARTUP VK OK
```

Если бот перезапускается, сначала проверьте `migrate`, затем `db`, затем `bot`.

## 7. Обновление через GitHub

1. Перед обновлением создайте резервную копию PostgreSQL.
2. Распакуйте новый архив локально.
3. Замените файлы проекта в репозитории, но не загружайте `.env`, дампы базы,
   каталог `secrets` и реальные токены.
4. Проверьте, что `docker-compose.yml` остался в корне репозитория.
5. Загрузите изменения в отдельную ветку или Pull Request.
6. Дождитесь зелёного результата GitHub Actions **Validate Docker release**.
7. После проверки объедините изменения в ветку `main`.
8. Откройте Portainer → Stacks → `vk-taxi`.
9. Нажмите **Pull and redeploy** или **Update the stack**.
10. Включите повторную сборку образа (**Re-pull image / Rebuild**), если
    Portainer показывает такую опцию.

Старый контейнер работает, пока строится новый образ. Затем Portainer заменяет его. Перерыв обычно составляет 5–30 секунд.

Полностью параллельный запуск двух экземпляров VK-бота не используется: это может вызвать двойную обработку событий и таймеров. База, заявки, очередь сообщений и постоянные таймеры сохраняются.

## 8. Автоматические GitOps-обновления

Если версия Portainer поддерживает GitOps updates:

1. Stack → Git repository settings.
2. Включите Automatic updates.
3. Выберите Polling или Webhook.
4. Для production безопаснее сначала использовать ручной **Pull and redeploy**.

Перед автоматическими обновлениями рекомендуется настроить внешние резервные копии базы.

## 9. Редактирование ENV

1. Portainer → Stacks → `vk-taxi`.
2. Environment variables.
3. Измените нужное значение.
4. Нажмите **Update the stack**.

Не редактируйте переменные внутри запущенного контейнера: при пересоздании они исчезнут.

Смена `POSTGRES_PASSWORD` после первого запуска требует отдельной смены пароля внутри PostgreSQL. Не меняйте эту переменную обычным редактированием Stack.

## 10. Старая база BotHost

Создание новой пустой базы проходит полностью через интерфейс Portainer. Для переноса существующей базы нужен файл `.dump` и один из вариантов:

- импорт базы средствами панели DockerHosting;
- восстановление через Portainer Console;
- однократная помощь администратора сервера;
- SSH-инструкция из `README_DOCKERHOSTING.md`.

Перед финальной копией остановите старого бота. Старый и новый бот не должны работать одновременно.

## 11. Безопасность

- Репозиторий должен быть приватным.
- GitHub PAT — только read-only и только для одного репозитория.
- Не добавляйте токены и пароли в Compose или Git.
- Не публикуйте PostgreSQL-порт `5432`.
- Ограничьте доступ к `3000`, а затем подключите HTTPS.
- Защитите Portainer HTTPS и сложным паролем.
- Создавайте резервные копии базы вне VPS.

## 12. Архивирование и сброс заявок

Во вкладке **«Заказы»** отдельно показаны обычные заявки и предварительные брони.
Excel содержит два листа: **«Заказы»** и **«Брони»**.

Сброс можно выполнить в любой момент:

1. Нажмите **«Скачать Excel и сбросить заявки»**.
2. Подтвердите действие в появившемся окне.
3. Сохраните автоматически сформированный Excel.

В Excel попадают и затем удаляются только завершённые, отменённые и закрытые без
водителя заявки, а также завершённые и отменённые брони. Ожидающие, назначенные и
выполняемые заявки остаются в базе вместе с очередью пассажиров, очередью водителей
и действующими таймерами.

Сохраняются пользователи, роли, отзывы, рейтинги, сведения «Моя машина», платёжные
реквизиты, блокировки, ложные вызовы, комиссии и напоминания о неоплаченных ложных
вызовах. Операция записывается в журнал администратора.
