# Установка V179

Исправления подготовлены в исходниках, на ваш сервер автоматически не установлены.

## До обновления

1. Сохраните текущий .env и резервную копию PostgreSQL (инструкция в scripts/backup.sh).
2. Сохраните возможность отката на V178. Зафиксируйте активные заявки.
3. По возможности обновляйтесь при небольшой нагрузке: пересоздание bot даст
   короткий перерыв. Убедитесь, что работает только ОДИН контейнер бота с этой БД.

## Docker Compose

Обновите исходники и docker-compose.yml из V179, сохранив ваш .env, downloads,
secrets и существующие именованные тома. Не создавайте новую БД.
Из каталога текущего развёртывания:

```bash
docker compose config --quiet
docker compose up -d --no-deps --build bot
docker compose logs --tail=120 -f bot
```

Новых миграций нет. Эти команды не пересоздают PostgreSQL и admin.
Общий образ имеет тег vk-taxi-app:v179; работающий контейнер admin не меняется
до его отдельного пересоздания. Его исходники и настройки защиты не изменены.
НЕ выполняйте docker compose down -v: это удалит данные.

## Portainer

Обновите репозиторий/исходники, из которых ваш Stack собирает образ, включая
Dockerfile и Compose. Выполните обновление с пересборкой, убедитесь, что bot
использует новый образ v179 (обычный Restart старого контейнера не обновляет код).
Если требуется оставить admin работающим без пересоздания, используйте точечное
обновление bot через Compose выше или эквивалентный выбор сервиса в доступном
интерфейсе. При обновлении всего Stack возможен перезапуск других сервисов.
Не меняйте имена томов и подключение к существующей БД.

Все новые параметры имеют значения по умолчанию в Compose: старый .env можно
сохранить. Для изменения лимитов доступны:

```dotenv
BOT_WATCHDOG_ENABLED=1
BOT_TASK_TIMEOUT=180
BOT_STARTUP_TIMEOUT=180
BOT_POLL_STALL_TIMEOUT=90
BOT_OUTBOX_STALL_TIMEOUT=90
BOT_DB_STATEMENT_TIMEOUT_MS=30000
BOT_DB_LOCK_TIMEOUT_MS=5000
BOT_DB_IDLE_TRANSACTION_TIMEOUT_MS=60000
```

Не уменьшайте лимиты без наблюдений: тяжёлая операция не должна ошибочно
считаться зависанием. Watchdog рассчитан на Docker restart: unless-stopped.
При запуске без Docker нужен внешний менеджер процессов, перезапускающий бот
после ненулевого выхода (например, systemd Restart=on-failure). Запуск вручную
в терминале не обеспечивает автоматическое восстановление.

## После обновления

- Дождитесь STARTUP DATABASE OK, STARTUP VK OK, STARTUP BOT OK и сообщения
  Bot watchdog ready. После миграции строки бота должны иметь дату/время.
- Проверьте пассажирское меню, место водителя на линии и обычную заявку:
  предложение → принятие → подача → завершение. Затем персональную и
  параллельную заявку, отмену и таймаут отказа.
- Убедитесь, что старая оценка больше не порождает callback каждые 15 секунд.
  Возможно предупреждение Stopped VK cosmetic edit: серверная оценка уже закрыта.
- Проверьте push на актуальном устройстве. Для UnregisteredError ожидается
  Disabled unregistered Firebase device, без повторных traceback на этот токен.
- При срабатывании watchdog сохраните журнал со стеками. Повторяющиеся
  перезапуски — сигнал неисправности, а не нормальная работа: проверяются VK,
  подключение/блокировки БД, CPU/RAM и параметры лимитов.

Проверка локальных тестов с Python 3.11:

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -p 'test_*.py'
```

Тесты не подключаются к реальному VK/Firebase. ORM-сценарии используют SQLite
в отдельном процессе: они проверяют сохранение состояния, НЕ блокировки PostgreSQL.
Нужна проверка на вашем сервере; нагрузочный тест и реальная задержка ответов
в этой среде не измерялись.
