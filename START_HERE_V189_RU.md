# V189 — исправления после подробной проверки

Используйте этот архив вместо ранее выданного V188. Файлы CHANGES_V188_RU.md, QA_V188_RU.md и qa_v188/ оставлены как история; текущий результат описан здесь и в QA_V189_RU.md.

## Исправлено

1. **Единый срок обычного предложения.** При неудачной передаче в водительскую восстанавливается только оставшаяся часть исходных 60 секунд. Старое значение driver_accept_timeout больше не создаёт другой срок в этом ответвлении. Повторный ввод/открытие меню не продлевает окно.
2. **Ранний таймер не теряет восстановление.** Обработчик сначала проверяет владельца, затем повторно планирует оставшееся время с постоянной записью. Старый callback не перепланирует предложение другого водителя.
3. **Персональный счётчик параллельных заявок.** Учитываются ЧС, линия и маршрут именно этого водителя. При нуле старое уведомление снимается прежним механизмом синхронизации.
4. **Карточка доставки.** Исходные кнопки времени закрываются при принятии доставки. Перед созданием следующей карточки подтверждения/срока выполнения дополнительно закрывается оставшееся старое предложение. Время до клиента и время выполнения доставки не объединены: согласование стоимости сохранено.
5. **Параллельное принятие только выбором ETA.** Первое открытие из списка/чата создаёт резерв решения, а не принятую следующую поездку. Автоматическое предложение сразу содержит времена. Чужое предложение, просроченная кнопка и новый запрет ЧС не позволяют принять заявку.
6. **60 секунд и для нового параллельного предложения.** Повторное открытие не продлевает срок. После выбора времени запрос актуальности для старой заявки сохраняет уже выбранный ETA и не просит вводить его повторно. Старый 120-секундный путь оставлен только для совместимости с заявками, принятыми предыдущей версией без ETA.
7. **Текущая поездка не отменяется при таймауте параллельной.** Убирается будущая доступность на линии; статус выполняемой поездки и её водитель не меняются. Не сбрасывается ввод стоимости/чат текущей поездки. Новая заявка снова распределяется, проигнорированная не предлагается сразу тому же водителю автоматически. Своевременный отказ от параллельной заявки с линии не снимает.
8. **Защита резервов.** Обычный подбор, личное взятие из водительского чата и переговоры о цене не перехватывают активный резерв параллельного ETA. Серверная проекция приложения видит такой резерв и убирает просроченные действия.
9. **Конкурирующие операции.** Выбор ETA делегируется до блокировки заявки; принятие и таймаут используют порядок водитель → текущая поездка → следующая заявка. Снимок заявки перечитывается после получения блокировки. Это проверка кода и автономных сценариев, НЕ нагрузочный тест PostgreSQL.

## База и установка

Новых полей/таблиц относительно V188 не добавлено. Вершина миграций остаётся `0059_driver_blacklist` (после 0058_arrival_notice). При обновлении исходного проекта из первого архива миграция 0059 обязательна. Сделайте резервную копию БД и исходников, проверьте `alembic upgrade head` на копии базы, затем запускайте бота и админку из одной версии. BotHost использует штатную миграцию при запуске. Не запускайте старый и новый бот одновременно.

**Это кандидат исходников для проверки на стенде.** Реальные PostgreSQL/VK/Firebase и Android-устройство здесь не были доступны. Архив не развёрнут на вашем сервере. Android APK не пересобирался. Без стенда гарантировать отсутствие всех регрессий нельзя.
