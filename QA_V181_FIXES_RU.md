# Проверки V181 — исправления восьми согласованных пунктов

## Окружение

- Python 3.11.18, изолированное окружение, зависимости закреплены requirements.txt.
- SQLite для ORM/состояний. Никаких вызовов рабочего PostgreSQL, VK, FCM или изменений на сервере.
- В проверках полного графа импортов HTTP-вызовы жёстко запрещены; Long Poll, отправка сообщений, FCM и запуск таймеров заменены заглушками.

## Результаты

- Синтаксический разбор: все 262 Python-файла без ошибок.
- Исходный архив без изменений: 849 тестов, 844 успешных, 4 failures + 1 error.
- Архив с исправлениями: 850 тестов, 845 успешных, 4 failures + 1 error. Все пять проблем совпадают с исходным архивом; новых непройденных проверок нет.
- Новый изолированный сценарный набор: 22 теста (включая 7 тестов полных импортированных обработчиков). Все проходят. Он запускается отдельным процессом из общей регрессии, поскольку старые тесты подменяют common.models в своём процессе.
- Проверки V180 ORM/API и V179 ORM также выполнялись с установленными зависимостями, не пропускались из-за отсутствующего SQLAlchemy.

## Новое покрытие

- Переход к параллельной заявке: цена 350 / 0 / отсутствует, сохранение источника ГС, назначение driver_id, удаление parallel_driver_id.
- Чат в обе стороны по закреплённой параллельной заявке при наличии другой текущей поездки; явный вход по новой кнопке; запрет чужой/закрытой заявки и устаревшей привязки; сохранение состояния ввода итоговой суммы.
- Ответ диспетчера голосовым водителю параллельной заявки; создание реальной диспетчерской голосовой заявки полными обработчиками и передача следующему водителю с сохранённым исходным вложением.
- Вложенный пересланный ГС, подготовка для разных получателей, обновление старой приватной doc-ссылки.
- Единая карточка водитель/авто/госномер/ETA/вопрос. «Да» обновляет её и добавляет «Машинка в пути» без повторного уведомления водителя; «Нет» отменяет без второй формы подтверждения. При прибытии карточка сохраняется без старого вопроса.
- Итог с внутренним ID 10500 использует публичный номер 3000. Проверено также завершение текущей поездки и полный переход к следующей с ценой клиента.
- Новые подписи кнопок и сохранение всех прежних причин отказа.
- Передача в водительскую: @all, цена, первый в очереди, точный текст пассажиру, отсутствие FIFO-переназначения, защита от повторного клика и восстановление предложения при недоступном чате.
- Персональная заявка: точный текст отказа и отсутствие утечки в общий чат.

## Существовавшие до исправлений проблемы регрессии

Не исправлялись и не скрывались:

1. test_requirements_v163_direct_selection_dedup — test_message_identity_wins_over_unstable_event_id: код использует event_id раньше идентичности сообщения.
2. Тот же файл — test_user_state_transitions_are_database_serialized: тест ищет старый комментарий/row lock внутри handler; код уже использует advisory lock перед handler.
3. Тот же файл — test_duplicate_order_creation_is_stopped_before_draft_processing: расположение duplicate guard относительно чтения draft не соответствует контракту теста.
4. Тот же файл — test_direct_offer_failure_logs_exact_reason: нет ожидаемого rejection_reasons в логировании.
5. test_requirements_v172_remove_calculator — test_calculation_code_and_defaults_removed: остался файл bot/price_calculator.py.

Это контрактные/source-проверки; их наличие не является само по себе доказательством каждого соответствующего runtime-дефекта. Изменённые старые тесты обновлены только под новые согласованные требования.

## Что обязательно проверить на стенде

1. Реальный VK: прямое и пересланное голосовое диспетчера проигрывается у первого и следующего водителя; ГС доступно после принятия и при переходе к параллельной.
2. Переписка текущего и параллельного пассажира не смешивается; кнопка параллельного чата отвечает нужному пассажиру; после перехода остаётся правильная привязка.
3. Пассажир видит одну карточку с авто/водителем/ETA. После «Да, жду» из неё уходят вопрос/кнопки, появляется «Машинка в пути». После «Нет» заявка отменяется по действующим правилам.
4. Новый вариант отказа сохраняет водителя первым на его линии; в настроенную беседу приходит @all; пассажир получает согласованный текст. У бота есть права на беседу/упоминания.
5. Публичная нумерация после сброса совпадает в карточке и итоговом сообщении.
6. Конкурентные ответы/отмена/приём заявок в PostgreSQL, восстановление после рестарта и живой FCM. SQLite и заглушки этого не доказывают.

Тесты не означают готовности всей исходной V180-dev к боевому использованию: карты, фоновая навигация и новый Android APK не завершены этим серверным исправлением. APK в архиве остаётся исходной версией 1.6.
